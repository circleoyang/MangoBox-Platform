Device Manager 安裝與使用說明

v0.4.8-rc13Windows 64-bit PortableMangoX2 / MangoLite

Device Manager 用於 MangoBox 的日常裝置管理：連線裝置、查看 Runtime 狀態、設定模組與 GPIO／Pin、備份與還原設定、校準，以及支援範圍內的即時讀值與監看。韌體燒錄、Clean Flash、Factory Reset、Recovery／Deep Rescue 請改用 Hardware Lab。

1. 下載與安裝

1
下載官方 Windows ZIP

從上方按鈕或 MangoBox 下載中心取得 MangoBox-Device-Manager-v0.4.8-rc13-windows.zip。

2
完整解壓縮

將 ZIP 解壓到一般資料夾，例如「文件」或桌面上的 MangoBox 資料夾。不要直接在 ZIP 壓縮檔內執行程式。

3
啟動程式

執行 MangoBox_Device_Manager_v0.4.8-rc13.exe。此版本為 Portable，不需要安裝 Python，也不需要執行傳統安裝程式。

若 Windows SmartScreen 第一次執行時出現保護提示，請先確認檔案確實來自本站的 GitHub Release，再依 Windows 提示選擇「其他資訊／仍要執行」。
官方 Release SHA-256：4e2d9c4e97046f4268f871cbd5b600ae9912cb315b11670886cb67e154048146

2. 第一次連線

  1. 以 USB 將 MangoX2 或 MangoLite 連接到電腦。
  2. 開啟 Device Manager，在上方選擇適合的「連線方式」。
  3. 按「重新整理」，確認清單中出現正確的 COM Port。
  4. 選擇 COM Port 後按「連線」。
  5. 連線成功後，先在「首頁」確認裝置名稱、Runtime Version、Target 與連線狀態，再進行設定。
同一個 MicroUSB COM Port 同一時間只能由一個程式控制。若 Thonny 正在連線 Pico，Device Manager 可能無法開啟該 COM Port；請先在 Thonny 停止程式並中斷／釋放 MicroPython 連線。

3. 兩種常用連線方式

連線方式適合情境接線注意事項
MicroUSB / Pico高層 MicroPython 教學、裝置設定、支援範圍內的感測器讀值／監看、OLED 字型管理。Pico 原生 MicroUSB／USB 資料線。使用前先讓 Thonny 釋放 Pico COM Port。Device Manager 會辨識 Pico / MicroPython 類型連接埠。
Runtime UART透過正在執行的 Mango Runtime 做管理與即時控制。USB-to-TTL 接到該板的 Host UART。程式會等待 Runtime readiness 回應；COM 開啟不代表 Runtime 已準備完成。

Device Manager v0.4.8-rc13 支援 MangoX2 + Pico、MangoX2 + Pico 2 W、MangoLite + Pico 2 W。不同 Target 可用功能會依 Runtime、模組啟用狀態與硬體配置而不同。

4. 模組與 GPIO／Pin 設定

建議操作順序

  1. 先連線裝置，進入「腳位設定」。
  2. 按「從裝置讀取設定」，以 Runtime 目前真正的設定為基準。
  3. 從裝置清單選擇要修改的模組，或使用「新增裝置」。
  4. 設定 Enable、GPIO／Pin、Pull、Active、Debounce 或該模組需要的參數。
  5. 確認畫面沒有 GPIO 衝突或固定腳位限制。
  6. 按「儲存變更」。設定會送到 Runtime。
  7. 若畫面提示需要重新啟動，請執行 Reboot，讓既有 device instance 全部使用新設定。
固定板載硬體不應任意改腳位。Device Manager 會依 Target 與 Runtime 的 Pin Policy 鎖定固定資源；ADC 類感測器也只能使用支援 ADC 的 GPIO。
不要以別的板型設定檔直接套用。匯入時請確認 Board / Target 相符，並仔細檢查變更摘要。

5. 即時測試與監看

連線與設定完成後，可依目前 Target／Runtime 支援情況使用 Device Manager 的控制與監看頁面，例如：

  • RGB 燈：單顆／全部點亮、亮度、燈效。
  • OLED：文字顯示、閃爍與預覽。
  • 蜂鳴器：單音、蜂鳴、樂曲與停止。
  • 輸入／Servo：Button / Cap Touch 狀態監看、Servo 定位與角度操作。
  • 感測器頁：依 Runtime 已實作 Student API 與模組狀態，提供 Read Once、Start Monitor、Stop Monitor，以及 Light / Sound / Joystick 等既有校準流程。
v0.4.8-rc13 的感測器路徑優先使用 MangoBox Student API。若目前 Runtime 支援該 API 但模組未啟用或腳位設定錯誤，Device Manager 會顯示 Runtime／Student API 錯誤，不會偷偷繞過設定直接讀 GPIO。

監看沒有反應時

  1. 先確認模組是否 Enabled。
  2. 確認 GPIO／Pin 與實際接線一致。
  3. 停止 Monitor 後再 Start 一次。
  4. 確認沒有 Thonny 或其他程式同時佔用同一 COM Port。
  5. 仍無法判斷時，再進 Hardware Lab 檢查韌體、執行模式或裝置生命週期。

6. 設定備份、匯入與還原

功能用途效果
匯出目前設定保存目前裝置配置。產生設定備份檔。
匯入／套用設定選擇性套用備份中的變更。屬於 merge / update；可在摘要中選擇要套用的項目。
完整還原備份把裝置完整恢復到某份備份。完整 replace；目前存在但備份沒有的自訂項目可能被移除，完成後會重新啟動。
恢復預設配置回到 Runtime 隨韌體提供的預設設定。預設值以 Runtime bundled defaults 為唯一來源。
「完整還原備份」與「恢復預設配置」都不是一般試按按鈕。執行前請先匯出目前設定，並確認備份屬於同一個 Board / Target。

7. OLED 中文字型管理

若高層 MicroPython 專題需要在 OLED 顯示中文，可使用「OLED 字型管理」分析並寫入所需中文字模。

  1. 使用 MicroUSB / Pico 連線。
  2. 先讓 Thonny 釋放 Pico COM Port。
  3. 開啟「OLED 字型管理」。
  4. 貼上預計顯示的中文句子，或從 Python 程式掃描。
  5. 先「分析缺字」，再選擇「只寫入缺少字」。

學生程式仍使用一般高層 API，不需要自行處理字模檔案。

8. 常見問題

找不到 Pico MicroUSB COM Port

  • 確認 USB 線具有資料傳輸功能。
  • 按「重新整理」。
  • 關閉或中斷 Thonny 的 MicroPython backend。
  • 若有多個 Pico，請手動確認正確 COM Port。

Runtime UART 找到 COM Port，但一直等待

  • 確認 USB-to-TTL TX/RX/GND 接線正確。
  • 確認裝置已完成開機動畫／聲音。
  • 確認裝置目前執行模式允許 Runtime UART。

改了 Pin 但硬體還在舊腳位

儲存後重新啟動裝置。部分已建立的 device instance 需要 reboot 才會完整套用新腳位。

何時應改用 Hardware Lab？

遇到韌體更新、Clean Flash、Factory Reset、Recovery／Deep Rescue、執行模式無法切回、裝置無法正常進入 Runtime 等問題時，請使用 Hardware Lab，而不是在 Device Manager 反覆改 Pin。
