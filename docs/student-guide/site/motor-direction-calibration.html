Motor Direction Calibration

Motor Direction Calibration 用來處理「車體實際組裝方向」與程式邏輯不一致的情況。例如左右馬達插座互換、某一側馬達接線方向相反，學生仍然應該能用相同的 forward() / backward() 程式控制車體。

設計原則：這是 Motor / Drive 層的車體校正，不是 BLE 專屬設定。BLE、UART、Gateway、循線與 High-Level MicroPython 都共用同一套車體方向語意。

四個核心設定

drive.left_motor
drive.right_motor
drive.left_inverted
drive.right_inverted
  • left_motor / right_motor：決定邏輯左右輪分別對應實體 M1 或 M2。
  • left_inverted / right_inverted：決定該側車輪是否反轉。

預設基線維持 MangoBox 既有車體語意：左輪使用 M2、右輪使用 M1；左輪不反轉、右輪反轉。

什麼情況要改哪一個？

實機現象建議調整
左右輪插座互換交換 left_motor / right_motor
只有左輪方向相反切換 left_inverted
只有右輪方向相反切換 right_inverted
Forward 整台往後、Backward 整台往前檢查兩輪 inversion，避免用學生程式硬改 forward / backward

在 Device Manager 中校正

  1. 連線到裝置。
  2. 進入 Motor / Drive 相關設定頁。
  3. 先用 M1 / M2 raw test 確認每個實體 channel 是否能正常轉動。
  4. 確認哪一顆實體 Motor 是車體左輪、哪一顆是右輪。
  5. 設定 Left Motor / Right Motor。
  6. 若單側方向相反，切換該側 Inverted。
  7. 儲存設定。
  8. 用 Forward / Backward 測試車體語意。

新版 Runtime 在設定儲存後會讓下一個 Drive command 直接使用新的 Drive profile，不需要重新開機。

Raw Motor 與 Drive 的差別

M1 / M2 raw motor 操作故意保留「實體通道」語意，方便接線與硬體診斷；它不會自動套用車體 inversion。相對地，forward()、backward()、tank、arc、spin 等 Drive 命令會套用邏輯左右輪映射與 inversion。

給學生的程式應該維持不變

from mangobox import Mango

m = Mango()
m.forward(60)
# 車體應該真的向前，不需要學生知道 M1 / M2 如何安裝。

校正完成後，學生可以專注在「車體要做什麼」，而不是處理每一台車的配線差異。
